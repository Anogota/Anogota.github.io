Mirai demonstrates one of the fastest-growing attack vectors in modern times; improperly configured IoT devices. This attack vector is constantly on the rise as more and more IoT devices are being created and deployed around the globe, and is actively being exploited by a wide variety of botnets. Internal IoT devices are also being used for long-term persistence by malicious actors.

### Privilege Escalation

At first, i've test sudo -l
```terminal
~/Desktop $ sudo -l
Matching Defaults entries for pi on localhost:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin

User pi may run the following commands on localhost:
    (ALL : ALL) ALL
    (ALL) NOPASSWD: ALL
```
And we are able to log in as a root without credentials.
```terminal
pi@raspberrypi:~/Desktop $ sudo su
root@raspberrypi:/home/pi/Desktop#
```
So let's navigate to /root and obtain a root.txt
But after check what's inside in root.txt, here the announcement.
```bash
root@raspberrypi:~# cat root.txt
I lost my original root.txt! I think I may have a backup on my USB stick...
```
We can use a lsblk that is the command, that writes out information about devices - such as hard drive, usb stick.

At first we can see a usbstick in /media directory, let's navigate to there.
```terminal
root@raspberrypi:~# cd /media/usbstick

Damnit! Sorry man I accidentally deleted your files off the USB stick.
```

We can see that James accidentally deleted our files.
When we are deleting files, that didn't delete the content of the file. That only removes the entry in the directory; /dev/sdb is a raw block device.
That is, a sequence of bytes in the form in which they reside on the storage medium. When can you use the strings command, because processes arbitrary binary data and outputs only sequences of printable characters.

### Sumary

Attack chain: HTTP enumeration → identified Raspberry Pi admin panel → default pi:raspberry credentials → SSH access → passwordless sudo (full root) → recovered a "deleted" flag from the raw USB device using strings.

Mirai is a good, practical demonstration of how dangerous unchanged default credentials can be, especially on IoT devices that are often deployed and forgotten. Privilege escalation required no effort at all, since pi had unrestricted sudo access. The most memorable part of the box was the final twist: James had deleted root.txt from the USB stick, but the actual data was still recoverable at the raw block-device level with strings, since deleting a file only removes its directory entry, not the data itself.
Remediation is simple: change default credentials on every device, disable root/sudo access for standard users whenever possible, and remember that deleted files are not truly gone until they're overwritten.
